# 技术 PPT 吹牛措辞（Tech PPT Hype Copywriting）

## 用途与边界

把朴素的技术描述写成有记忆点、有技术分量、有价值指向的 PPT、汇报、路演或宣传文案。保留用户想要的气势、黑话和概念包装，但每次拔高都要落在具体机制、场景、结果或目标上。

适用于技术亮点包装、技术项目介绍、成果汇报与技术产品命名。普通邮件润色、学术结论改写和 PPT 文件制作不单独触发本 skill；用户明确要求时，可将文案作为相关任务的一部分。

## 核心原则

1. **包装强度只改变表达，不改变证据门槛。** 对内汇报、政府材料和融资路演都保留同一事实边界。修辞可以更有气势，不能新增数字、排名、合作方、原创性或商业化成果。
2. **有数据用数据，没数据讲机制。** 缺少实测依据时，用算法机制、适用场景、流程与可复核输出增强技术分量；不自动补精度、时延、效率或量级。目标、估算与实测须保持原来的状态。
3. **把价值讲清楚。** 根据听众选择痛点、方案、技术差异与业务价值的叙事顺序；不强迫每段都套同一个模板。价值推断不能写成已实现收益。
4. **能力用词须有对应条件。** 自写模块不自动等于完全自主可控，模块联动不自动等于自主闭环，计划迭代不等于自进化。选词前核对能力范围。
5. **领先性须有可比依据。** “第一梯队”“率先”“领先”同样需要对比对象、指标、条件和日期。加上场景限定或换成含蓄措辞不能替代证据。

## 改写流程

1. **拆事实与状态**：提取功能、方法、数字、场景、人员贡献及合作关系，区分已实现功能、已测量结果、当前进展、计划目标和待确认信息。材料不足时先完成可依据的部分；只追问影响核心表述的缺失信息。
2. **选叙事**：需要组织段落、标题或发布会表达时，读 [叙事框架与模板](references/templates-and-cases.md)。模板中的占位符只用真实材料填充；缺失时改为有依据的定性句或单列待补信息。
3. **配词**：需要技术包装词、量化表达或黑话时，读 [七层词库](references/vocabulary.md)，按使用条件选词。
4. **组句**：优先形成“主张 + 具体锚点 + 价值指向”。按页面容量决定标题、短句或讲稿长度，避免黑话堆叠。
5. **核对边界**：检查新增事实、指标口径、能力范围、验证状态、贡献归属与修辞强度。阶段成果可以展示，但不能升级为现场验证、正式验收或商业落地。

## 场合与火力

| 场合 | 默认火力 | 表达重点 |
|---|---|---|
| 评奖答辩、职称答辩、严肃立项 | 低—中 | 技术问题、机制、可比结果与本人贡献 |
| 政府通稿、产业宣传、媒体报道 | 中—高 | 场景故事、产业价值与有依据的成果 |
| 公司内汇报、晋升答辩 | 中 | 已做工作、能力积累、业务影响与下一步决策 |
| 融资路演、发布会 | 高 | 记忆点、用户利益、市场假设与发展目标 |

火力调整标题、节奏、意象和修辞。所有场合都遵守上述事实边界。用户未指定时按场合选档，不必每次提示调档。

## 技术命名

需要给技术、产品、平台、架构起名时，读 [国风与工程意象命名](references/naming-mythology.md)。可参考华为、比亚迪、小米、小鹏等企业的不同表达方式，选择文化意象、功能隐喻、工程描述或中英文组合。

基本路径：**技术核心特性 → 可理解的意象 → 概念名 + 品类后缀 + 一句解释**。典籍出处仅在核实后使用；普通创意名可以直接写寓意。参考既有名称的方法，另创候选，不把他人品牌名直接作为用户产品名。

## 交付形式

- 文案：直接给可粘贴的标题和正文；需要时补一条改写说明。仅在存在依据缺口时，将待补信息简短列在正文之外。
- 命名：默认给 3—5 个候选，列明名字、品类后缀、技术映射和一句传播文案；推荐一个并说明取舍。仅在确有需要时附读音、英文代号或核实后的典籍出处。
- 对外正式启用名称时，根据用户需要检索重名与商标；无法核实则标明未检索，不宣称可注册。创意起名阶段无需强制开展注册调查。
